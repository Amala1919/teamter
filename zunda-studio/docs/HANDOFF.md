## ローカルで始める

```
git clone https://github.com/Amala1919/teamter.git
cd teamter
git checkout claude/shadowverse-digital-cardgame-pkuaad
cd zunda-studio
```

- アプリを動かす: Windows なら `起動.bat` をダブルクリック(部品の用意とビルドもする)。`起動.bat dev` で開発モード。
- 確かめる: `npm run typecheck` / `npx vitest run` / `npm run build:app && npm run build:devhost && npx playwright test`(初回は `npx playwright install chromium`)。
- 新しい作業はブランチを切って、`claude/shadowverse-digital-cardgame-pkuaad` へ PR を出す。

## Windows でのテスト

- 模擬コマンド(`tests/fixtures/bin/*`)は拡張子なしの Node のスクリプトなので、Windows では同じ名前の `.cmd` を起動する(テストでは `fixtureCommand(name)` を使う)。
- E2E の模擬 AI の応答の置き場所は OS の一時フォルダ(`/tmp` は Windows ではドライブごとに別の場所になる)。
- `run.exe` が要るエンジンの起動・自動インストールのテストは、Windows では飛ばす(模擬のエンジンを exe にできない)。
- アプリ側も直した: AI の中止・時間切れで `claude.cmd` などの中の本体まで止める(`killTree`。taskkill /T)、書き出しを中止したら ffmpeg の終了を待ってから途中のファイルを消す。

## 利用者の環境

- Windows で使っている(エラーの報告は Windows の ffmpeg のもの)。C ドライブの空きが少ない。
- 書き出しのメモリ不足は、Linux で Windows の書き込みの動きを模して直した。Windows の実機ではまだ確かめていない(直したあと、利用者から次の報告は来ていない)。

## 残っていること・提案中のこと

- **VOICEVOX のエンジン本体の置き場所を変えられるようにする**(提案中、返事待ち)。「自動で入れて起動」で入れたエンジン(1〜2GB)は `%APPDATA%\zunda-studio\engines` にあり、#27 のキャッシュの移動の対象外。`src/main/core/services.ts` の `EngineInstaller` の `root`。
- 「今すぐ起動し直す」(設定 → 保存場所)で Electron が実際に起動し直すところは、テストでは確かめていない(`app.relaunch()` + `app.quit()`)。実機で一度確かめたい。
- 「削除して詰める」の「ほかの素材が残っている時間は詰めない」は、消した区間の中で終わる素材だけを見ている(区間より後ろまで続く素材があっても詰める)。区間いっぱい止めるようにするかは、利用者に聞いたまま。
- 動画プレビューの E2E(「止めている間は止めたコマが映り続ける」など)が、全体で流したときにまれに1回だけ失敗する。単体で繰り返すと通る。原因は分かっていない。
- **書き出しの高速化**: 測ると、書き出しの時間は1コマずつ描く方(Node のキャンバス + 画素の受け渡し)で決まり、GPU のエンコーダにしてもほぼ変わらなかった(1080p 10秒で CPU 10.5〜13秒 / NVENC 11.5〜12秒)。速くするなら、区間に分けて worker で並列に描き、最後につなぐのが次の候補(提案のみ)。
- プレビューでは、動画の速さが4倍を超えると音が出ない(Chromium の制限。書き出しでは出る)。待ち時間の早送りは音が気にならない区間に使う想定。
