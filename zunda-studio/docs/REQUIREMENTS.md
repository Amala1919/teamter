# 要件定義

## 1. 目的とスコープ

合成音声によるゲーム実況動画(いわゆるずんだもん実況/ゆっくり実況)を、台本の執筆からYouTubeへの投稿素材の書き出しまで一貫して作れるデスクトップアプリを作る。編集操作の中心はYMM4に近いタイムラインとし、そこにAIチャットによる台本生成・編集指示を統合する。

### 動画の形式

**2人の掛け合い**を前提とする。

- **ずんだもん(投稿者本人の役)**: セリフは人間が書く
- **相方(AIが演じる役)**: セリフはAIが、設定された性格・口調に従って書く

つまりAIは編集アシスタントであると同時に**共演者**である。投稿者が自分のセリフを書くと、AIが相方として返答を書き、その往復がそのまま台本になる。この「会話として台本を書ける」ことが本アプリの中心的な価値である。

3人以上の構成や、両方のセリフを人間が書く構成も、キャラクターごとの設定として表現できるようにする(役割は固定の仕様ではなくキャラクターの属性とする)。

### 対象ユーザー

YouTubeにゲーム実況を投稿する個人。自分の声は使わず合成音声で語らせる形式を採る。動画編集ソフトの操作自体には慣れていなくてもよいが、素材(ゲーム録画・立ち絵・BGM)は自分で用意できる。

### 明確に作らないもの

| 作らないもの | 理由 |
| --- | --- |
| 生実況音声を動画の音声として使うこと | 語りは合成音声のみとする。設計上、後から音声トラックとして追加できる余地は残す(文字起こしはライブモードの入力手段として使うが、録音した声を動画に載せることはしない) |
| 汎用ノンリニア編集ソフト(Premiere等の代替) | 合成音声実況という用途に特化することで、必要な操作を絞れる |
| クラウドでのレンダリング・共同編集 | 単一ユーザーのローカル完結を前提とする |
| 音声ライブラリ・立ち絵・BGMの同梱 | ライセンスの問題。ユーザーが用意した素材を読み込む |
| AviUtl(.exo)への出力 | 本アプリ内で書き出しまで完結させる |

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| アイテム | タイムライン上に置かれる編集要素の最小単位(ボイス、動画、画像、字幕、音声、図形など) |
| ボイスアイテム | セリフのテキストを持つアイテム。音声合成結果・字幕・口パク情報が一体で紐づく |
| キャラクター | 話者・話速・立ち絵・字幕スタイルをまとめたプリセット。「ずんだもん」「四国めたん」など |
| 執筆役割 | そのキャラクターのセリフを誰が書くか。`user`(人間が書く) か `ai`(AIが書く) のいずれか |
| 相方 | 執筆役割が `ai` のキャラクター。AIが演じる共演者 |
| ペルソナ | 相方の性格・口調・掛け合いでの立ち位置の設定。AIがセリフを書くときの拠り所 |
| 立ち絵 | キャラクターの全身画像。PSDの多層構造で表情・口・目のパーツを差し替える |
| 台本 | ボイスアイテムを発話順に並べたもの。テキストとしても編集できるビューを持つ |
| プロジェクト | 素材への参照・タイムライン・キャラクター設定を含む編集状態全体(1つのJSONファイル) |
| 編集コマンド | プロジェクトに対する1つの変更操作。手動編集・AI編集の双方がこれを経由する |
| ライブセッション | ゲームを録画している最中にAIと交わした会話の記録。録画上の時刻と対応付けられる |
| ライブモード | 録画中に使う軽量な会話用の画面。プレイを妨げないことを優先する |

## 3. 機能要件

優先度は `MUST`(MVPに必須) / `SHOULD`(MVP後に必要) / `MAY`(あれば良い)。

### 3.1 台本とボイス

| ID | 要件 | 優先度 |
| --- | --- | --- |
| V-1 | セリフのテキストとキャラクターを指定すると、VOICEVOXで音声を合成し、ボイスアイテムとしてタイムラインに配置できる | MUST |
| V-2 | 台本ビューで複数行のセリフを連続入力すると、行ごとにボイスアイテムが生成され、発話順に隙間なく並ぶ | MUST |
| V-3 | ボイスアイテムごとに話速・音高・抑揚・音量を調整でき、キャラクターの既定値を上書きできる | MUST |
| V-4 | セリフを編集すると音声が再合成され、アイテムの長さと後続アイテムの位置が追従する(追従するかは設定で選べる) | MUST |
| V-5 | 合成音声はキャッシュし、同一の文とパラメータであれば再合成しない | MUST |
| V-6 | 読み方(アクセント・イントネーション)をモーラ単位で修正でき、修正内容は辞書として保存できる | SHOULD |
| V-7 | 複数の音声エンジン(VOICEVOX / AivisSpeech / COEIROINK)を切り替えられる | SHOULD |

### 3.2 字幕

| ID | 要件 | 優先度 |
| --- | --- | --- |
| S-1 | ボイスアイテムのテキストが字幕として自動表示され、音声と同じ区間に同期する | MUST |
| S-2 | 字幕スタイル(フォント、サイズ、色、縁取り、影、配置)をキャラクター単位のプリセットとして持てる | MUST |
| S-3 | 字幕は画面幅に応じて自動改行され、指定文字数での強制改行もできる | MUST |
| S-4 | 個別のアイテムでプリセットを上書きし、強調表示(色変え・拡大)ができる | SHOULD |
| S-5 | 字幕を焼き込みではなくソフト字幕(SRT/VTT)として書き出せる | MAY |

### 3.3 立ち絵

| ID | 要件 | 優先度 |
| --- | --- | --- |
| P-1 | PSDファイルを立ち絵として読み込み、レイヤーツリーを解析してパーツ候補を提示できる | MUST |
| P-2 | ユーザーがレイヤーグループを「目」「口」「眉」「その他」などの役割に割り当て、その対応をキャラクター設定として保存できる | MUST |
| P-3 | 口パクは2方式に対応する: (a) 合成音声のモーラ情報から母音(あいうえおん)に対応するパーツを割り当てる方式、(b) 開閉段階順に並べたパーツを音量で切り替える方式 | MUST |
| P-4 | まばたきは開→閉の順に並べたパーツを一定周期+ゆらぎで再生する | MUST |
| P-5 | 表情(目・眉・口のパーツ組み合わせ)を名前付きプリセットとして保存し、アイテム単位で指定できる | MUST |
| P-6 | 立ち絵の位置・拡大率・反転・前後関係を設定でき、キャラクターごとの既定位置を持つ | MUST |
| P-7 | PSD以外に、パーツごとのPNGフォルダ構成の立ち絵も読み込める | MAY |

立ち絵のパーツ認識はレイヤー名の命名規約(`*` や `!` の接頭辞)に依存させない。規約があればパーツ役割の自動推定のヒントとして使うが、最終的な対応付けはユーザー(またはAI)が明示的に行い、プロジェクトに保存する。これは素材によって命名が統一されていない現実に合わせるためである。

### 3.4 映像・音声素材

| ID | 要件 | 優先度 |
| --- | --- | --- |
| M-1 | ゲーム録画(mp4等)をタイムラインに配置し、イン点/アウト点を指定して切り出せる | MUST |
| M-2 | 画像を配置でき、表示区間とトランスフォームを設定できる | MUST |
| M-3 | BGM・効果音を配置でき、音量・フェード・ループを設定できる | MUST |
| M-4 | セリフの再生中はBGMを自動的に下げる(オートダッキング) | SHOULD |
| M-5 | 長時間の録画でも快適に扱えるよう、低解像度のプロキシを生成して編集時に使う | SHOULD |
| M-6 | 図形・枠・単色背景を配置できる | SHOULD |

### 3.5 タイムラインとエフェクト

| ID | 要件 | 優先度 |
| --- | --- | --- |
| T-1 | 複数レイヤーを持つタイムラインで、アイテムをドラッグで移動・伸縮・並べ替えできる | MUST |
| T-2 | プレビューを再生・シーク・フレーム単位で移動でき、プレビューと書き出し結果が一致する | MUST |
| T-3 | フェード、拡大縮小、移動、振動などの基本エフェクトをアイテムに付けられる | SHOULD |
| T-4 | すべての編集操作をundo/redoできる | MUST |
| T-5 | 編集中の状態を自動保存し、クラッシュ後に復元できる | SHOULD |

### 3.6 掛け合い(AIが演じる相方)

このアプリの中心となる機能。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| B-1 | キャラクターごとに執筆役割(`user` / `ai`)を設定でき、台本ビュー上でどちらが書く役か識別できる | MUST |
| B-2 | 相方のペルソナ(性格、口調、一人称、掛け合いでの立ち位置、NG表現、返答の目安の長さ)を設定でき、プロジェクトに保存される | MUST |
| B-3 | 自分のセリフを書いて指示すると、AIが相方として次のセリフを生成し、ボイスアイテムとして台本に追加される | MUST |
| B-4 | AIは直前までの会話全体を踏まえて返答する。話題の流れとキャラクターの一貫性を保つ | MUST |
| B-5 | 生成された返答は採用前に確認でき、破棄・再生成・手動修正ができる | MUST |
| B-6 | 生成された相方のセリフは人間が書いたセリフと同じデータ構造になり、以降は区別なく編集できる | MUST |
| B-7 | 複数の候補を生成して選べる | SHOULD |
| B-8 | 相方に続けて複数往復を生成させ、会話の続きをまとめて作れる | SHOULD |
| B-9 | ペルソナをプロジェクトをまたいで再利用できる(相方の設定を書き出し・読み込みできる) | SHOULD |
| B-10 | 自分のセリフについてもAIに提案させられる(ネタが出ないときの補助) | MAY |

AIが生成するのは相方のセリフに限る。投稿者本人の役のセリフをAIが勝手に書き換えることはしない(指示があった場合を除く)。これは自分の役の一貫性を投稿者が握っていられるようにするためである。

### 3.7 ライブセッション(録画中のAI相談と記録)

ゲームをプレイして録画している最中に、AIに質問・相談ができ、その会話が録画上の時刻付きで記録される。編集時にその記録を見て「どこで何を話したか」を振り返り、そのまま台本の素材にできる。

プレイ中に思いついたことや詰まったことは、あとから思い出せない。この機能はそれを記録として残し、編集作業の出発点にする。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| R-1 | 録画中に使える軽量なライブモードがあり、ゲームの操作を妨げずにAIと会話できる | MUST |
| R-2 | 会話の各発言が、録画上の時刻と対応付けて記録される | MUST |
| R-3 | ライブモードのAIは相方と同じペルソナで応答する。録画中の会話と動画内の掛け合いで人格が変わらない | MUST |
| R-4 | 編集時にセッションの記録を一覧・検索でき、発言を選ぶとプレビューがその時刻に移動する | MUST |
| R-5 | 記録の発言を選んで台本に採用できる(自分の発言は自分の役のセリフ、AIの発言は相方のセリフになる) | MUST |
| R-6 | 録画とセッションの時刻のずれを後から調整できる | MUST |
| R-7 | 音声入力(押しながら話す)で会話でき、発話は文字に起こして記録される | SHOULD |
| R-8 | AIの返答を音声で聞ける。出力先の音声デバイスを選べ、録画に混ざるかどうかを制御できる | SHOULD |
| R-9 | プレイ中にホットキーで目印を打てる(「ここ面白かった」)。目印は編集時にタイムライン上に表示される | SHOULD |
| R-10 | OBSと連携して録画の開始時刻とファイルを取得し、時刻の対応付けを自動で行う | SHOULD |
| R-11 | ライブモードは短く速く応答する(プレイを止めないため、編集時のチャットとは別のモデル設定を持てる) | SHOULD |
| R-12 | セッションの記録をテキストとして書き出せる | MAY |
| R-13 | ライブモードの会話から、話した内容をもとに台本の下書きをまとめて生成できる | MAY |

音声入力は「自分の声を動画に使う」こととは別である。録音した声は文字起こしの入力としてのみ使い、動画の音声には合成音声を使う。

### 3.8 AIチャット(編集指示)

| ID | 要件 | 優先度 |
| --- | --- | --- |
| A-1 | チャットで指示すると、プロジェクトへの編集コマンド列が生成され、適用前に差分として確認できる | MUST |
| A-2 | AIは台本を推敲できる(尺の調整、テンポの改善、口調の統一) | MUST |
| A-3 | AIはセリフの内容に応じて表情プリセットを割り当てられる | MUST |
| A-4 | AIは既存のタイムラインを読み取れる。「12:30〜12:45の映像をこのセリフに当てて」のような素材配置指示に応答できる | MUST |
| A-5 | 企画メモとゲーム録画から、台本とタイムラインの下書きを一括生成できる | SHOULD |
| A-6 | 動画タイトル・概要欄・チャプター・クレジット文を生成できる | SHOULD |
| A-7 | AIの適用結果はundoで1操作としてまとめて取り消せる | MUST |
| A-8 | APIキーはユーザーが設定し、OSの安全な保管領域に保存する | MUST |
| A-9 | AIを一切使わずに手動編集だけで完成させられる(AIは常に任意) | MUST |

### 3.9 書き出し

| ID | 要件 | 優先度 |
| --- | --- | --- |
| E-1 | H.264/AACのmp4として書き出せ、解像度・フレームレート・ビットレートを指定できる | MUST |
| E-2 | 書き出しの進捗を表示し、中断できる | MUST |
| E-3 | 使用キャラクターから規約上必要なクレジット文を生成し、概要欄テキストとして出力できる | MUST |
| E-4 | チャプター付きの概要欄テキストを出力できる | SHOULD |
| E-5 | 部分書き出し(選択範囲のみ)ができる | MAY |

## 4. 非機能要件

| 分類 | 要件 |
| --- | --- |
| プラットフォーム | Windows 10/11を主対象とする。macOS/Linuxでも開発・動作できる構成にするが、検証優先度は下げる |
| 応答性 | セリフ入力から音声合成完了まで、短文で概ね1秒以内(ローカルCPU合成)。タイムライン操作は常に即応する |
| プレビュー | 1080p30のプロジェクトで、立ち絵2体+映像1本+字幕の構成をリアルタイム再生できる |
| 書き出し | 実時間の3倍以内を目標とする(1080p30、GPUエンコード利用時) |
| 大容量素材 | 数時間・数十GBの録画を読み込んでもメモリを圧迫しない。全体をメモリに載せない設計とする |
| 非破壊編集 | 元素材は一切書き換えない。編集内容はプロジェクトファイル内の参照と指示のみで表現する |
| ライブモードの応答 | プレイを止めないよう、質問から応答開始まで概ね2秒以内を目標とする |
| ライブモードの記録 | 記録はアプリが落ちても失われないよう、発言ごとに追記保存する |
| 音声の扱い | 音声入力の録音データは文字起こし後に破棄するか保持するかをユーザーが選べる。クラウドの文字起こしを使う場合は、音声が外部に送信されることを明示する |
| オフライン動作 | AIチャットとライブモードの応答以外のすべての機能はネットワークなしで動作する。文字起こしはローカルで完結させられる |
| データ保全 | プロジェクトの保存は原子的に行い、書き込み中のクラッシュで既存ファイルを壊さない |
| 決定性 | 同一プロジェクトからの書き出しは常に同一の結果になる(まばたきの乱数はプロジェクト内のシード値で固定する) |

## 5. ライセンス要件

これは機能要件と同格で扱う。規約違反を作り込むと、成果物を投稿できなくなるためである。

| ID | 要件 |
| --- | --- |
| L-1 | 音声ライブラリ・立ち絵素材・BGM・フォントをリポジトリおよび配布物に同梱しない |
| L-2 | VOICEVOX ENGINEはLGPL-3.0を含むデュアルライセンスであるため、公式配布物をそのまま利用する形をとり、改変して静的に取り込まない。エンジンの取得は初回セットアップ時のダウンロードとし、ライセンス文書を同梱して表示する |
| L-3 | 使用したキャラクターを追跡し、各音声ライブラリの規約に沿ったクレジット文(`VOICEVOX:ずんだもん` 等)を自動生成する |
| L-4 | 素材ごとに出典・利用条件・クレジット要否をプロジェクト内に記録し、書き出し時に一覧として確認できる |
| L-5 | AIが生成した台本・概要欄は投稿者が確認する前提とし、無確認での自動投稿機能は設けない |

## 6. 受け入れ条件(MVPの完成定義)

以下がすべて満たされた時点をMVP完成とする。

1. ゲーム録画1本と、ずんだもん・四国めたんの立ち絵(PSD)、BGM1曲を読み込める
2. ずんだもんを自分の役、もう一方をAIが演じる相方として設定でき、相方のペルソナを書ける
3. 自分のセリフを書くと相方の返答が生成され、採用すると音声・字幕・口パク付きのボイスアイテムとして台本に並ぶ。これを数往復繰り返して会話が成立する
4. 録画の任意区間を切り出して背景に配置し、プレビューで再生できる
5. チャットで「テンポを上げたいので各セリフを短くして」と指示すると、台本の差分が提示され、適用できる
6. 録画中にライブモードでAIに相談でき、その会話が編集時に録画上の時刻と対応して一覧でき、台本に採用できる
7. mp4として書き出し、YouTubeにそのまま投稿できる状態になる
8. 書き出し時にクレジット文が生成される
9. 相方のセリフを手動で書く運用に切り替えれば、上記の一連の操作をAIなしでも完遂できる
