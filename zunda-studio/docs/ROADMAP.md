# ロードマップ

各フェーズは「完了条件」を満たした時点で終わりとする。完了条件は実際に動くことで判定し、コードが書けたことでは判定しない。

フェーズの順序は「**AIより先に、AIが操作する対象を完成させる**」原則で決めている。タイムラインと書き出しが動かないうちにチャットを作っても、AIの出力が正しいか確認できない。

## 先行実装の余地

ライブセッションの**記録部分だけ**(テキスト入力・時刻の記録・目印)はAIにも編集機能にも依存しない。Phase 1 の直後にこれだけ先に作っておけば、編集機能を作っている間も録画のたびに素材を貯められる。あとから振り返れる記録は、貯めた期間の分だけ価値が出るので、早く動かす価値が大きい。

AIの応答を伴う部分はPhase 4のAI基盤が前提になるため、そこは後から足す。

## 進め方

各フェーズの中でも、**まず1本通す**ことを優先する。たとえばPhase 1では、話者一覧の取得を完璧にする前に「固定の話者IDで音声が鳴る」状態を先に作る。縦に1本通っていれば、その後の作業は常に動く状態から始められる。

完璧にしない代わりに、以下は最初から妥協しない。

- 時間はミリ秒の整数で扱う(後から直すと全体に波及する)
- 変更はコマンド経由にする(後から入れるのは事実上不可能)
- 描画はプレビューと書き出しで共有する(分けてから統合するのは困難)
- 素材のライセンス情報を持つ(後付けすると既存プロジェクトで欠落する)
